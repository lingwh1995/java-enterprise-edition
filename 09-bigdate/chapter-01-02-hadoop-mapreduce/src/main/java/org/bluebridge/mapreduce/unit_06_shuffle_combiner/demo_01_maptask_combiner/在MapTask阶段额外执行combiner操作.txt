3. 日志分析
   a. 开启 Combiner 后 Map output materialized bytes 值变小?
      - 开启 Combiner 并且成功执行后:Map output materialized bytes(Map 溢写到磁盘的数据大小)下降到 132
      - 本质:Combiner 在溢写磁盘前先做本地聚合，相同 key 多条记录合并成少量记录，写入磁盘的数据变少
   b. Map 溢写完整流程
      - Map 输出 KV -> 环形内存缓冲区 -> 缓冲区满 -> 触发 Spill(溢写)
   c. Map 溢写步骤
      - 对缓冲区数据分区、排序
      - 执行 Combiner(如果配置了)
      - 压缩 -> 写入本地磁盘(materialized 文件)
        - 没有 Combiner:多条同 key 数据原样全部写入磁盘
        - 开启 Combiner:同 key 多条记录先聚合合并，再写入磁盘
   d. Combine input records = 0 的两个典型场景
      - 数据全部存在环形缓冲区，没有发生 Spill，Combiner 只有 spill 溢写的时候才会执行
      - 整个 map 任务所有输出都待在内存，不用刷磁盘 -> 不触发 combiner
   e. Combine 注意事项
      - Hadoop MR 不保证 Combiner 一定执行，有可能这次运行生效、下次不生效
      - 所以业务逻辑绝对不能依赖 Combiner，它只是 shuffle 优化手段
   f. Combiner 触发时机
      - Combiner 在 spill 之前执行，有两种触发情况:
        - 缓冲区达到阈值(默认 80%) -> spill -> Combiner
        - Map 结束时 flush -> spill -> Combiner(即使数据量很小)
